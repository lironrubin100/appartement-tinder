# MVP technical execution defaults

Recorded 17 October 2026 under the owner's explicit delegation of technical recommendations. DECISIONS.md wins. This document closes technical mechanics; external-provider tests and legal review are separate release evidence. Existing compatible RPC names/tables must be reconciled before adding a migration.

## API and transactions

Production scoring has one owner: versioned SQL function behind authorized feed RPCs, after eligibility filtering and before paging. TypeScript reference may exist only as test oracle with parity fixtures; no client-owned computed score or duplicate production algorithm. Preserve C13 weights/coverage. C2 option/disclosure approval remains separate from technical scoring ownership.

Authenticated reads use no-store. Feed/inbox default page 20, maximum 50; messages default 50, maximum 100. Map viewport returns at most 500 safe pins with `truncated=true` and a zoom-in message when capped; never pretend the partial set is exhaustive. Reject nonfinite/out-of-range bounding boxes. Map and apartment eligibility require an available room satisfying all room-level filters in the same row.

Common adapter response: `{items,next_cursor,has_more,projection_version}`; map additionally returns truncation. Preserve existing RPC contracts by adding an adapter, rather than breaking deployed callers. Errors: `AUTH_REQUIRED`, privacy-preserving `NOT_FOUND`, `VALIDATION_FAILED` with allowlisted field/code, `VERSION_CONFLICT` with current revision only if authorized, `STATE_UNAVAILABLE`, `QUOTA_EXCEEDED` with retry_after_seconds, `CURSOR_STALE`, `PROVIDER_UNAVAILABLE`, `INTERNAL` with sanitized correlation ID. HTTP mapping 401/404/422/409/409/429/409/503/500 respectively.

Cursor is base64url serialized versioned fields plus HMAC: query hash, account binding where personalized, last sort tuple, source/scoring revision, expiry 30 minutes. Server verifies signature/context; changed filter or score revision explicitly restarts. Never put secrets or exact location in cursor. Apartment sort `(published_at DESC,id DESC)`; inbox `(last_message_seq timestamp DESC,conversation_id DESC)` with sequence tie per conversation; scored people `(coverage_tier ASC,score DESC,approved_activity_at DESC,id ASC)`. Activity is stored coarse last-active date, not public presence. Missing score is its own tier. Reconcile existing pagination compatibility first.

Mutations accept client-generated UUID request key unique by `(actor,operation,key)`. Store normalized payload hash and result reference: identical retry returns original result, key reused with different payload returns conflict. Keep dedupe tombstone for lifetime of referenced invitation/message/listing; never expire into duplicate creation. Message request key uniqueness scoped to `(conversation,sender,key)`. Edit accepts expected integer revision; transaction checks authorization and increments revision once. Do not return another actor's result on collision.

Lock order: account eligibility/quota row, listing or group parent sorted by ID, request/membership rows sorted by ID, conversation parent, then message/outbox writes. Acceptance rechecks all state under locks. Counter displays use relational COUNT of unique current saves and filtered available rooms; no separate user-writable counter authority. Index each named query/invariant with the feature's migration. Verify query plans using disposable fixtures; no full-table private-data payloads.

Daily invitation day is Asia/Jerusalem, using server time. Rolling chat rate limits follow F8. Atomic row/constraint checks are the enforcement boundary; never use module memory as distributed quota storage. Stable business settings default to canonical values, protected audit writes, versioned typed bounds. Structural constraints/permissions are migration constants, not an editable admin slider. No quota mutation on a shared target during QA.

## Chat, unread and typing

Each conversation has strictly increasing server sequence; membership stores `visible_after_seq` and monotonic `last_read_seq`. Read endpoint clamps to latest authorized visible sequence and applies GREATEST(current,new); never moves backward. Unread counts visible messages above marker whose sender differs from reader. Own send, typing, receipts and card save actions never increment sender's unread. Shared listing card is one actual message, counted once for other members.

Mark read only while thread is visible and document focused, after visible messages rendered. Other-tab updates may advance marker. Incoming Realtime signal triggers bounded catch-up from last persisted sequence; dedupe by message ID and sort server sequence. Database response resolves pending send; dropped socket is not evidence a send failed. Failed-send retry reuses request key.

One account inbox signal subscription and one active-thread channel per browser context. Authorized private channels, authenticated setAuth and server membership/visible-history checks; no public channel for private typing. On auth, block, suspension or membership change tear down/revalidate, and deny reads/writes at DB regardless of socket teardown. Test old subscription after revocation; if platform cannot enforce promptly, suppress sensitive payloads and fetch through authorized API rather than treating UI unsubscribe as security.

Typing broadcasts at most once per 2 seconds; typing expires after 5 seconds without renewal, clears on blur/thread exit/send. Never persist typing as message or notification. Read receipts expose authorized participants' markers only. Group join sees messages after agreed join sequence; account removal/blocked membership denies new reads, previews, sends, Realtime and notifications. Leaving follows F5 explicit reopen; no incoming-message auto-return.

## Lifecycle jobs and moderation

Listing renewal sets `renewed_at=server_now`, expires 45 days later; ordinary content edit does not renew automatically. Public eligibility checks expiry at read time, not just nightly job. Taken-report dedupe: one active contribution per reporter/listing/renewal cohort. Three distinct nonowner eligible reporters hide; renewal increments cohort, consumes old contributions, retains protected audit. Fresh reporting can hide again; operator can flag abusive contributions and reverse automatic hide. Manual reviewer restriction always dominates renewal. No other report category contributes to automatic taken count.

Unavailable room/listing pauses pending requests. Persist state `needs_reconfirmation`; requester explicitly reconfirms after reopening before owner can accept. Accepted conversations/grants preserved per D4; group existence changes no apartment state. New address/property requires a new listing. After publish, precise location is immutable through ordinary edit; correction uses a protected reviewed path that increments location version and reauthorizes grants. Do not implement arbitrary distance-based address substitution.

Group transfer invitation expires in 7 days; acceptance requires current eligible unblocked member and matching membership revision. Until accepted old admin remains. Last member exit archives group and expires pending invitations; no auto-assigned new admin. Account deletion immediate deactivation/revocation, cancellation before `delete_requested_at+30 days` and before purge claim starts. Cancellation restores account access only: hidden listings/group discovery require explicit reactivation; no withdrawn request or revoked grant silently resurrects.

Deletion job stores account ID, phase, cursor, attempts, lease_until, next_attempt_at and sanitized error. Lock account once, recheck grace/state, then idempotent owner-scoped phases (hide/revoke, owned Storage, private rows, identity anonymization), checkpoints between batches of 100. Lease 2 minutes; retries 1m/5m/30m/2h/12h then needs-operator state; operator retry explicit. Persist tombstone before auth removal. No unreviewed erasure of abuse evidence/shared messages. Exact retention/redaction for reports/shared message content remains legal release gate, not guessed by executor.

## Notification and measurement defaults

Events: `message_received`, `introduction_received`, `poster_invitation_received`, `listing_inquiry_received`, `request_accepted`, `group_invitation_received`, `admission_action_required`, `listing_hidden`, `listing_expiring`, `deletion_requested`. Each server-committed event has unique ID; recipient/channel deliveries unique. Product security/account notices remain visible in account state; optional outbound channels honor preferences.

Existing master switch retained exactly; new accounts master on for transactional notifications, event toggles on, email channel on only with verified address, push off until explicit device permission/subscription. No marketing/area alerts by default. Existing off remains off; existing missing event keys inherit master, never silently re-enable disabled users. No message body, exact location or private search data in lock-screen/email payloads.

Active-reading suppression: focused thread heartbeat every 15 seconds, valid for 30 seconds; do not send message email while active. Burst window 60 seconds per recipient/conversation; one digest event points to latest committed sequence. Recheck permissions/preferences/read marker before dispatch. Retry attempts at +1m,+5m,+30m,+2h,+12h with small jitter; max 6 including first attempt, lease 2m, then dead queue. 410/404 push endpoint disables that owned subscription. Provider outage never rolls back original message. Worker at-least-once; provider idempotency best effort, no exactly-once guarantee.

First-party pilot event store owner-read only, no direct arbitrary actor assignment from browser. Event enum/fields allowlist, unique event ID, UTC time and explicit QA/demo/pilot cohort. Raw pilot telemetry defaults 90 days then aggregate/deidentify under reviewed policy; disabling optional analytics prevents nonessential tracking. Legal review M3 remains required before real-user nonessential telemetry; local synthetic events can test pipeline now. No external analytics dependency to finish MVP.

## Map and address defaults

Autocomplete >=3 trimmed characters, debounce 300ms, maximum 5 suggestions, timeout 5 seconds; discard stale responses. Authenticated lookup limit 30 requests/account/minute and shared provider budget configured conservatively from verified plan, circuit-breaker on 429. Missing verified budget/key disables provider lookup with visible manual fallback, never unlimited traffic. Logs omit address query/raw results.

Server-signed selection token TTL 15 minutes, binds actor, normalized provider selection hash, exact coordinates, accuracy class and provider ID; token itself private, never analytics/cache. Publish verifies signature/actor/expiry and confirmed address. Manual route explicitly labeled: owner enters address, confirms pin and city, server validates coordinate ranges and plausible Israeli extent; no false provider-verified claim. Any edit to selected text invalidates token. No public Nominatim autocomplete.

Public location uses one persisted random point per property generated with cryptographically secure randomness in a 300–700m annulus, held separately from private exact coordinates. Reuse only under unchanged property identity; do not derive angle from public ID or re-randomize per response/reload, and never expose random seed/offset. Public displacement is approximate, not anonymity proof: synthetic inversion/averaging/boundary tests and user-text/photo disclosure review required before release. Preserve point across normal content edits; privacy migration rotates once only after explicit migration review, no permanent dual-point API. Limit public viewport queries to public points; infer no precise location from hidden distance/ordering endpoints.

Price filters inclusive per available room; available-by date means `available_from <= requested_date` (absent date unconstrained). Bills included requires all supported disclosed charges included, unknown/mixed does not match true. Invalid min>max returns field error. Explicit Search this area and accessible cluster overlap chooser follow D14. Provider quality/terms/commercial free-hosting feasibility remain evidence gates, with manual fallback independently implementable.
