# תוכנית העבודה להשלמת Shutaf MVP

עודכן 20 באוקטובר 2026. מקור ההחלטות: [DECISIONS](../DECISIONS.md). זהו סדר הביצוע; מצב המימוש והפרסום המדויק נמצא ב־[רשם הביצוע](planning/execution-state.json) וב־[סיכום הפרסום](releases/2026-10-20-profiles-chat.md). החבילה והשינויים המאומתים פורסמו; לא כל תוכנית ה־MVP הושלמה.

המיקוד: לבנות גרסה עובדת שאפשר להדגים לגופי מימון באוניברסיטה. עכשיו מבצעים מסעות דירה/שותפים/צ׳אט ומראים שימושיות ומדדים פשוטים; אין עוד החלטת תשתית מרכזית שזוהתה ומחכה לבעל המוצר. עיצוב וניסוחים ניתנים לשיפור בהמשך, והכנות להשקה רחבה אינן תנאי להתחלת הביצוע.

להמשך אוטומטי מספיק לומר ״עבוד על הפיצ׳ר הבא״. AGENTS מפנה ל־[START_NEXT_WORK](START_NEXT_WORK.md); `node scripts/next-work.mjs --json` בוחר חבילה לפי תלויות והתקדמות, והסוכן מתחזק את רשם הביצוע וה־handoff. אין צורך לבחור מזהה ידנית.

## ההחלטות האחרונות

- מפרסם ללא שאלון שותפים יכול לגלוש באנשים ובדירות. דף הפתיחה שלו נשאר הדירות שלי.
- הוא יכול לשלוח הזמנה המציגה אותו ודירה פעילה שלו. אישור הנמען פותח שיחה בהקשר הדירה. אין גישה לרשימת השומרים או לפרטי קשר פרטיים.
- שיתוף דירה בקבוצה הוא כרטיס בצ׳אט; כל חבר שומר עצמאית. אין רשימת שמורים קבוצתית נפרדת ב־MVP.
- המלצות הארכיטקטורה והטיפול בדיווחים אומצו. המכניקה מתועדת ב־[TECHNICAL_DEFAULTS](specs/TECHNICAL_DEFAULTS.md); פרטי המוצר ב־DECISIONS. אין צורך לשאול שוב על RPC, עימוד, נעילות, קאש, ניסיונות חוזרים או מונה לא נקראים.

## Definition of done לכל חבילה

הסוכן קורא את החבילה וההחלטות הנדרשות בלבד, בודק מה כבר קיים, מבצע רק את החסר, בודק הרשאות/שמירה/התאוששות ולא רק build, מפנה fixtures רק כשאינם מיועדים להישמר להדגמה לפי הוראת הבעלים, ומעדכן את ה־handoff. `implemented`, `verified`, `integrated`, `deployed` הם מצבים שונים. מחסור במפתח ספק חוסם רק את בדיקת הספק; לא מעניק רשות לדלג על בדיקות שניתן להריץ.

דוגמת dispatch היסטורית לפני אישור הפרסום הקבוע (17 באוקטובר; כיום ממשיכים לפי AGENTS ו־START_NEXT_WORK):

> Work on packet SL00.1 from docs/EXECUTION_PACKETS.md following AGENTS.md and docs/EXECUTION_PROTOCOL.md. Reconcile existing implementation; execute only this packet; update the shared handoff. Do not apply hosted migrations, commit, push or deploy.

## המיקוד הנוכחי: גרסה עובדת להצגת ערך

הבהרת בעל המוצר: קודם מוצר עובד ותשתית ביצוע שמקדמת אותו; המטרה היא להציג שימושיות ופוטנציאל לגופי מימון באוניברסיטה, ולא להכין כרגע השקה ציבורית רחבה. אין לפתוח החלטות סגורות, ואין לעכב את הבנייה לצורך ליטוש עיצובי/ניסוחים או דיון משפטי כללי. אין הבטחה למימון; מדגימים תועלת אמיתית ויכולת להתקדם.

קדימות: מסד פיתוח מבודד ובסיס עובד -> תיקון קליטת חשבון ומונה צ׳אט -> מסע דירה מלא -> פניות בהסכמה משני הכיוונים -> קבוצות ושיתוף -> בדיקות אמינות ומדדים פשוטים -> גימור התאמה. שומרים על הרשאות ופרטיות כחלק ממימוש נכון; הן אינן פרויקט משפטי נפרד לפני כתיבת הקוד. בדיקות ספק/מדיניות נרשמות רק בשלב שבו באמת נדרשות להפעלה הרלוונטית, בלי לחסום עבודה מקומית או הדגמה בנתונים סינתטיים.

תוצר ההדגמה: דירה אמיתית או מסומנת demo עם חדרים/מחירים, חיפוש מועיל, פנייה שהנמען מאשר, צ׳אט שנשמר ועובד, וקבוצה שמשתפת דירה וכל אחד שומר עצמאית. דוח פשוט מציג היצע פעיל, השלמת פרופיל, פניות, אישורים, שיחות דו־צדדיות וזמן תגובה; מפרידים demo/QA ממשתמשי פיילוט. בהמשך מוסיפים תוצאות שימוש אמיתיות בהיקף קטן. אלה יעדי המוצר שלנו, לא טענה שאלו תנאי קבלה מחייבים של קרן מסוימת.
